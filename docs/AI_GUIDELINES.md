# AI Guidelines – StepUp

Provide this file as context when using an AI coding assistant (Cursor, Copilot, Claude).

## Project Structure

```
apps/
  backend/          # FastAPI + SQLAlchemy + Alembic
    app/
      api/v1/       # Route handlers
      services/     # Business logic
      repositories/ # DB queries
      models/       # SQLAlchemy models
      schemas/      # Pydantic schemas
      enums/        # Enum definitions
    tests/
      unit/         # Service unit tests
      integration/  # API integration tests
  frontend/         # React + Vite + TypeScript + Tailwind
    src/
      features/     # Feature modules (each feature has its own folder)
      components/   # Shared UI components
      constants/    # API endpoints, routes
      lib/          # apiClient, utilities
      types/        # api.ts (generated by openapi-typescript)
    tests/e2e/      # Playwright E2E tests
```

## Backend Rules

### DO
- Use the service layer for every endpoint – no business logic in routers
- Follow repository pattern – no raw SQL directly in services
- Pydantic schemas: `XxxCreate` for requests, `XxxResponse` for responses
- Pull error messages from `app/errors/messages.py`
- Write an integration test for every new endpoint
- Add audit logs for significant actions

### DO NOT
- Call `db.execute()` directly inside a router
- Use `from_attributes` in schemas without `model_config`
- Write raw SQL via `op.execute()` in migrations when Alembic operations suffice

### Layer Order

```
Router → Service → Repository → Model
```

### Adding a New Endpoint

1. Add field to model (if needed)
2. Create Alembic migration
3. Add field to schema
4. Add query to repository
5. Add business logic to service
6. Add endpoint to router
7. Write integration test

## Frontend Rules

### DO
- Keep all API calls inside `services/`
- Use types from `src/types/api.ts` in components
- Prefix hooks with `use`
- Every feature folder should have `hooks/`, `pages/`, `services/` subfolders

### DO NOT
- Call `axios` or `fetch` directly inside a component
- Use the `any` type (add a comment if absolutely unavoidable)
- Hardcode API URLs – use `constants/apiEndpoints.ts`
- Hardcode route strings – use `constants/routes.ts`

### State Management

- Server state: `apiClient` (axios) + local useState
- Auth state: `useAuthStore` (Zustand)
- Form state: local useState

## Test Rules

### Backend
- At least 1 unit test per service method
- At least 1 integration test per endpoint (happy path)
- Write separate tests for error cases

### Frontend
- Component tests: `@testing-library/react`
- Mocking: use `vi.mock()` for service functions
- E2E: Playwright for critical user flows

## Naming Conventions

| Type | Format | Example |
|------|--------|---------|
| Backend file | snake_case | `user_service.py` |
| Backend class | PascalCase | `UserService` |
| Frontend file | PascalCase | `UsersPage.tsx` |
| Frontend hook | camelCase | `useUsersPage.ts` |
| Frontend service | camelCase | `userService.ts` |
| CSS class | Tailwind utility | `bg-blue-700` |
